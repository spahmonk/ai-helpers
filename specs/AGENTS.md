# AI Agent Rules for `ai-helpers`

## Назначение
Этот файл задаёт правила для AI-агентов и автоматизированных помощников, работающих с репозиторием `ai-helpers`.

---

# 1. Общие правила

1. Сначала спецификация, потом код.
2. Не добавлять сетевое поведение в core-модули.
3. Не обходить path jail.
4. Не расширять shell execution за пределы whitelist-first policy.
5. Не сохранять сырые секреты, env vars или auth outputs.
6. Любое изменение compression logic требует regression и adversarial tests.
7. Любое изменение memory persistence требует security review.
8. Любое изменение stats должно сохранять корректность `saved_bytes` и `saved_tokens`.
9. Любое изменение audit/doctor должно делать поведение системы более объяснимым, а не менее.
10. Если есть сомнение между удобством и безопасностью — выбирать безопасность.

---

# 2. Правила работы со спецификациями

Перед реализацией сложной фичи агент должен:
- проверить наличие spec;
- если spec нет — предложить его создать;
- если поведение меняется — обновить spec/architecture.

---

# 3. Правила работы с кодом

Агент должен:
- предпочитать маленькие изменения большим;
- разделять contracts, core logic, integration и diagnostics;
- не смешивать CLI/MCP adapters с бизнес-логикой;
- поддерживать тестируемость.

---

# 4. Правила работы с shell и файлами

Агенту запрещено:
- добавлять shell-команды с file write behavior;
- добавлять remote-fetch команды в безопасный shell path;
- расширять file access вне root jail;
- добавлять неявные обходы ограничений.

---

# 5. Правила работы с памятью

Агент должен:
- хранить только полезные summaries и refs;
- избегать хранения raw content без необходимости;
- всегда учитывать redaction before persist;
- уважать retention и privacy model.

---

# 6. Правила тестирования

Для любого изменения:
- нужны тесты;
- bugfix требует regression test;
- security-sensitive change требует negative tests;
- compression changes требуют adversarial tests.

---

# 7. Правила выпуска

Перед предложением merge/release агент должен убедиться:
- release checklist актуален;
- docs обновлены;
- tests зелёные;
- local-only invariant не нарушен.

---

# 8. Основная цель

`ai-helpers` должен быть репозиторием качественных, локальных, безопасных инженерных модулей.  
Любая автоматизация, делающая систему менее прозрачной, считается нежелательной.
